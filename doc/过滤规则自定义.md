# 过滤规则自定义

## 功能说明

评论采集的排除型过滤规则由用户在设置页自定义（此前硬编码在
`CommentFetcher.EXCLUDE_PATTERNS` 中，仅内置"第X季"、"更新"两条）。

- 入口：设置页 → **采集参数** → **过滤规则**（附加提示词下方，点击进入二级页面）；
- 规则为正则表达式（`containsMatchIn` 语义，评论含匹配子串即命中），按列表顺序编号为
  **过滤器 1、2、3...**；
- 命中任一规则的评论被丢弃、不交给 AI；**字数下限过滤同样由规则实现**
  （默认规则 1 = `[\s\S]{15,}`，等价"少于 15 字丢弃"，不再硬编码）；
- 清空全部规则 = 不做任何过滤。

## 规则页面（FilterRulesActivity）

无页面级保存按钮，**每一步操作即时落盘**（写 remote prefs，下次采集即生效）：

- 条目单行展示：**编号（固定 3 位：001、002...）** | 正则文本（超长省略）+
  第二行灰色小字备注（无备注不显示） | 编辑按钮 | 删除按钮；
- **编辑 / 添加共用同一个 Dialog**：正则输入（实时校验，非法/为空时"保存"不可点）+
  备注输入（标注规则适用情况，可选）；右下角"保存"；
  有未保存修改时点返回/浮层外区域会先弹出"保存修改？"（保存 / 不保存 / 继续编辑）；
- **删除需二次确认**（确认框展示正则原文；删除后立即生效，后续规则编号顺延补位）；
- 右下角**圆形 FAB"+"**添加规则（新规则编号 = 现有数量 + 1）；
- 首次打开（配置项从未写入过）时预填内置默认规则（含备注），可直接修改或删除。

## 生效方式与存储

- 配置以 **JSON 对象数组**写入 libxposed remote preferences
  （`ModuleConfig.KEY_EXCLUDE_RULES`，key 为 `exclude_rules`，
  元素格式 `{"pattern":"正则","note":"备注"}`，兼容读取旧版纯字符串数组）；
- 宿主进程采集侧（`CommentFetcher.excludePatterns()`）在**每页解析时实时读取**并编译正则
  （无效正则跳过，不中断采集）——规则页任一操作保存后**下次拉取评论即生效，
  无需重启红果短剧**；
- 采集侧从未读到配置项时回退内置默认规则（老版本行为兼容）；配置损坏同样回退默认。

## 日志标记

被丢弃的评论在日志库 `comment.drop_reason`（DB v4 新增列）中记录丢弃原因：

- 命中正则：`命中过滤器Z,规则XXXX`（Z = 规则顺序编号，XXXX = 命中时的正则原文——
  用户后续修改规则不影响历史记录的展示）。字数下限同样是一条规则，
  如默认规则 1 命中时记录 `命中过滤器1,规则[\s\S]{15,}`。

日志二级页（LogViewerActivity）中，红色评论展开后标记由
"未交给 AI（被过滤丢弃）"改为 **"未交给AI, 命中过滤器Z,规则XXXX"**
（旧版本记录无 reason 字段，回退通用文案）。

## 兼容性说明

- 数据库 v3 → v4 通过 `onUpgrade` 增列，历史日志保留；
- 模块 App（日志查看）比宿主端代码新时（宿主库还是 v3），root 直读通道会探测
  `drop_reason` 列是否存在，不存在则回退旧查询（无原因标记）；
- TCP 通道由宿主端 `LogStore.readLog` 输出，宿主未升级时自然无 `reason` 字段，
  模块端按缺省处理。
