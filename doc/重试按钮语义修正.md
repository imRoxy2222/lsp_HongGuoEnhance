# 重试按钮语义修正

## 问题

词条页 AI 总结失败（如模型接口报错）后，状态栏出现"重试"按钮，
但点击后实际执行的是 `Pipeline.loadMore`——即**拉取一批新评论 +
增量总结**，行为等同"继续加载"：

- 模型没坏、只是暂时报错时，用户只想重发同一条请求，却额外消耗
  了一次评论 RPC 和一批新评论；
- 旧评论 + 新评论合并发送，token 消耗也会持续增长。

这不符合"重试"语义，更像"加载更多"。

## 修正

### `TagDialog.kt`

重试按钮点击事件由 `Pipeline.loadMore(seriesId)` 改为
`Pipeline.retry(seriesId)`。

### `Pipeline.kt` 新增 `retry(seriesId)`

```kotlin
fun retry(seriesId: String) {
    // COLLECTING / AI_PENDING 进行中直接忽略（防重复触发）
    if (cache.comments.isEmpty()) startInitialCollect(seriesId)  // 一条评论都没有：退回重新采集
    else runAi(seriesId)                                          // 有评论：全量重发 AI
}
```

| 失败场景 | 重试行为 |
|---|---|
| AI 总结失败（评论已采集） | **不拉新评论**，把 `cache.comments` 全量重发给 AI（全量模式，非增量），成功后覆盖旧词条 |
| 首次采集就失败（0 条评论） | 退回 `startInitialCollect` 重新采集 |
| "继续加载"中途失败（已有部分评论） | 用已有评论重试 AI（不再追加新页） |

与"继续加载"的语义区分：

- **重试** = 同一批数据重新请求 AI，数据集不变；
- **继续加载** = 拉取下一批新评论 + 增量总结（旧词条合并计数）。
