# 二级页面 LSPosed 服务未连接修复

## 问题现象

设置页显示"LSPosed 框架服务：已连接"，但从设置页进入二级页面（过滤规则页）后，
页面显示"未检测到 LSPosed 服务"。重启模块 App 与红果短剧均无效。

## 根因

libxposed-service 102 的 `XposedServiceHelper` 实现限制（查看库源码确认）：

1. **全局只保存单个 listener**——`registerListener` 直接 `mListener = listener`
   覆盖前一个，后注册者取代先注册者；
2. **框架投递的 binder 只回放一次**——`XposedProvider`（ContentProvider，进程内
   最先初始化）收到框架 binder 时若尚无 listener 则放入缓存；首次
   `registerListener` 回放缓存后**清空缓存**，此后 binder 不会再投递
   （进程生命周期内框架只发一次）。

于是各页面各自 `registerListener` 的写法下：

| 页面 | 结果 |
|---|---|
| MainActivity（首个注册） | 回放缓存 → 正常连接 |
| FilterRulesActivity（第二个注册） | 缓存已空、binder 不再投递 → 永远收不到 `onServiceBind`，显示"未连接" |
| LogViewerActivity | 同样收不到，但 root 直读通道不依赖 XposedService，问题被掩盖未暴露 |

## 修复方式

服务绑定提升为**进程级单例**，全进程只注册一次：

- 新增 `XposedServiceHolder.kt`：持有 `service` 状态，在
  `Application.onCreate` 中调用 `XposedServiceHelper.registerListener`（仅此一处），
  页面通过 `addListener`/`removeListener` 订阅；订阅时若服务已连接会**立即同步回调**；
- 新增 `App.kt`（自定义 Application，Manifest `android:name=".App"`）触发注册；
- `MainActivity` / `LogViewerActivity` / `FilterRulesActivity` 统一改为在
  `onCreate` 订阅、`onDestroy` 退订（顺带修复了原实现页面重建时 listener 泄漏）。

时序保证：`XposedProvider` 收 binder（缓存）→ `App.onCreate` 注册（回放）→
Activity 订阅（已连接则立即回调）→ 页面正常读写配置。

## 涉及文件

| 文件 | 改动 |
|---|---|
| `XposedServiceHolder.kt` | 新增：进程级服务单例 + 页面订阅机制 |
| `App.kt` | 新增：Application 入口，注册服务监听 |
| `AndroidManifest.xml` | `<application>` 增加 `android:name=".App"` |
| `MainActivity.kt` / `LogViewerActivity.kt` / `FilterRulesActivity.kt` | 移除各自的 `XposedServiceHelper.registerListener`，改订阅 `XposedServiceHolder`；`onDestroy` 退订 |

## 验证

- `gradlew :app:assembleDebug` 编译通过；
- 安装后依次打开：设置主页（已连接）→ 过滤规则页（应显示已连接并可加载/保存规则）；
  日志页无 root 时 TCP 通道也应恢复正常（此前 token 一直为空）。
