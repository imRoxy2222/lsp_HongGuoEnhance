# 评论词条日志

## 功能

"评论词条"每次采集 / AI 总结都会持久化到 **SQLite** 数据库，并可在
**HongGuoEnhance 模块 App 内**以两级页面查看：

1. **一级页**：按剧列表，显示剧名（未拿到剧名时显示 `剧 <seriesId>`）、
   seriesId、最近更新时间、评论数与 AI 调用次数，按最近使用降序；
2. **二级页**：单剧评论流——
   - 展示**全部抓取到的评论**（含被过滤丢弃的）；
   - 每条评论默认显示 2 行（超长省略），**点击展开/收起**；
   - 每条评论左侧有一根**竖条**：宽度固定为 1% 屏宽，**高度等于该条当前展示的
     行数高度**（默认 2 行，展开后自动延长）；
   - 竖条颜色：**绿色 = 该评论通过过滤、已交给 AI 提取词条；红色 = 被过滤丢弃，
     未交给 AI**。展开后底部有文字标注；
   - 同一批采集的评论归在"采集 N 条 · 交给 AI M 条 · 时间"小节标题下。
3. **右下角 FAB**（"AI 记录 N"）：进入 AI 调用记录页——
   - 每次 AI 调用一张卡片：时间、基于评论数；
   - **发送给 AI 的内容**：仅提供"复制"按钮（原文动辄数 KB，复制到其他应用查看）；
   - **AI 回复**：自动解析为 **KV 结构**展示（模型 / 输入输出 tokens /
     `词条 → ×次数`），并提供"复制原文"按钮查看原始 JSON；
   - 页面底部附流程异常记录（同样支持复制）。

**返回导航**：系统返回手势 / 返回键在二级、三级页逐级返回
（AI 记录页 → 单剧评论流 → 剧列表），一级页返回时才退出日志页
回到设置主页（`DetailScreen` 内经 `BackHandler` 处理）。

## 读取通道（root 直读优先，TCP 回退）

查看页按以下顺序取数：

1. **root 直读（优先，推荐）**：模块被授予 root（KernelSU / Magisk 均可）时，
   `su -c cat` 把宿主 DB（含 `-wal` / `-shm`）拉到模块 `cacheDir/hge_logs/`
   本地副本后直接查询——**不依赖宿主进程存活，无跨进程连接问题**。
   仅需 `su` 执行权，无需授予其他任何权限。
   - **路径定位**：宿主端经 remote preferences 上报真实数据库路径
     （`log_db_path`，`LogStore.reportDbPath`），模块优先使用；未同步到时
     依次回退 `/data/data/<宿主>/...` 与 `/data/user/0/<宿主>/...`；
   - **su 形态回退**：`su -c` 失败自动改用 `su --mount-master -c`
     （部分 root 实现默认在调用方 App 的受限挂载命名空间内执行，
     `/data/user` 下路径不可见，需切全局命名空间）；
   - **失败诊断**：所有候选都失败时，页面显示最后错误 + 各候选目录的
     `ls` 实际内容。
2. **宿主内嵌 TCP 服务（回退）**：未授权 root 时走 `127.0.0.1` 裸 TCP
   JSON 行协议（见下节）。

> 部分 ROM 的 SELinux 策略会拦截跨应用的 loopback 连接——即使宿主端已成功
> 监听端口，模块端 `connect()` 仍会被拒绝。root 直读是规避该限制的可靠手段。

## 为什么日志放在宿主私有目录

日志由 hook 代码产生，运行在**红果短剧进程**；查看页运行在**模块自身进程**。
模块进程无权限直接读取宿主私有数据库（SELinux per-app category 隔离）；
ContentProvider 方案也不可行（Android 11+ 包可见性会拦截宿主按 authority
访问模块的 provider，而宿主 manifest 无法修改）。

## 数据库结构

数据库：宿主 `filesDir/databases/hge_logs.db`（SQLiteOpenHelper，v1）。

| 表 | 字段 | 说明 |
|---|---|---|
| `series` | series_id PK / name / created / last_update | 剧索引，剧名可为空 |
| `comment` | _id / series_id / time / text / used | 抓取到的**全部**评论；used=1 交给 AI，used=0 被过滤丢弃（过滤规则：字数 ≤ 20） |
| `ai_log` | _id / series_id / time / base_count / request / response | 每次 AI 调用：request = 发送的完整请求体 JSON，response = AI 原始响应 |
| `error_log` | _id / series_id / time / msg | 采集 / AI 失败记录 |

同剧跨天共用同一行 series 与评论集；评论按 `_id` 升序即采集顺序。

## TCP 协议（仅 127.0.0.1，无 root 回退通道）

请求（UTF-8 一行 JSON + `\n`），响应（一行 JSON + `\n` 后断开）：

| 请求 | 响应 |
|---|---|
| `{"op":"ping"}` | `{"ok":true,"version":2}`（探测端口） |
| `{"op":"list"}` | `{"ok":true,"series":[{seriesId,name,lastUpdate,commentCount,aiCount}...]}` |
| `{"op":"log","seriesId":"123"}` | `{"ok":true,"data":{"comments":[...],"ai":[...],"errors":[...]}}`；无此剧返回 `{"ok":false,"error":"not found"}` |

- **端口**：`38080` 起依次尝试 12 个（`LogServer.PORT_BASE / PORT_TRIES`），
  模块端扫描相同区间；
- **鉴权**：设置页首次打开时生成 UUID 令牌写入 remote preferences（`log_token`），
  令牌非空时请求必须携带同值 `token` 字段。

## 服务启动时机（确定性拉起）

服务启动有三个互为兜底的入口，全部幂等：

1. **Application 创建时**（主要路径）：hook
   `android.app.Instrumentation.callApplicationOnCreate`，
   红果进程一起来就初始化存储并启动服务，**无需任何用户操作**；
2. **onPackageReady**：`ActivityThread.currentApplication()` 反射尝试
   （此时 Application 可能尚未创建，返回 null 则跳过）；
3. **首次点击分享**：`Pipeline.onShareClicked` 兜底。

**仅主进程生效**：Xposed 会注入宿主的全部进程（`:sandboxed_process0`、
`:push` 等子进程）。存储与服务只在主进程（进程名 == 包名）内启动，
子进程一律跳过（日志会打印 `log server skip: non-main process`）。
否则短命的沙箱子进程会抢绑端口后被系统回收，导致端口忽有忽无，
且其失败状态会覆盖主进程的真实上报。

绑定成功/失败都会写入 remote preferences 的 `log_server_status`
（`listening:<port>` / `bind_failed`），模块 App 的查看页在连接失败时
会读取并显示该状态，用于区分：

| 页面提示 | 含义 |
|---|---|
| 宿主端状态：未上报 | 红果进程内没有运行本模块的日志代码 → 强停红果重开；检查 LSPosed 是否启用模块 |
| 宿主端状态：服务已在 X 端口监听，但连接失败 | 服务在跑但通信异常 → 反馈排查 |
| 宿主端状态：端口绑定失败 | 宿主代码在运行但系统拒绝监听 → 到 LSPosed 管理器查模块日志 |

也可直接在 LSPosed 管理器 → 日志 → 模块日志 搜索 `log server`
确认绑定结果（`log server listening on 127.0.0.1:<port>`）。

## 自动清理（配置项）

设置页"评论词条日志"区：

| 配置 | remote key | 默认 | 说明 |
|---|---|---|---|
| 保留天数 | `log_retention_days` | 30 | 删除 `last_update` 早于 N 天的剧（级联删明细），0 = 禁用 |
| 总大小上限 MB | `log_max_size_mb` | 100 | 全部日志内容字符总量超限时，从最旧的剧开始级联删除，0 = 禁用 |

两种策略独立生效。清理在**宿主进程**执行（`LogStore.enforceRetention`）：
初始化时、每次追加后（限流：每小时最多检查一次）。

## 数据存放位置与生命周期

- 数据库在**红果短剧私有目录**（`filesDir/databases/hge_logs.db`），
  **不属于模块 App**——重装/更新 HongGuoEnhance 模块不会丢数据；
  卸载红果短剧才会清除；
- 模块 App 只是"查看器"：数据无法直接跨进程读取（SELinux 按应用隔离、
  ContentProvider 被 Android 11+ 包可见性拦截），必须由红果进程内的
  服务在 127.0.0.1 转发，因此查看时红果进程需存活；
- 模块 App 不持久化任何副本。

## 使用限制与注意

- 查看日志需红果短剧进程存活（前台或后台驻留均可）；进程被杀后数据仍在
  数据库里，重新打开红果即可继续查看；
- 更新模块 APK 后必须强停红果短剧并重开，宿主进程内的服务/存储代码才会更新；
- 剧名来源于剧评页 Intent 的 `seriesName`（见 分享按钮Hook.md 三路采集），
  用户未打开过该剧剧评页时一级页用 `剧 <seriesId>` 占位，seriesId 始终是唯一键。
